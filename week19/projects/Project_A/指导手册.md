### 6.3 构建Docker镜像

在项目根目录（`EDU/Project_A/`）执行：

```bash
# Windows PowerShell
cd EDU\Project_A
docker build -t risk-api:latest .

# Linux/macOS
cd EDU/Project_A
docker build -t risk-api:latest .
```

**参数说明**：
- `-t risk-api:latest`：指定镜像名称和标签
- `.`：使用当前目录作为构建上下文

**构建过程**：
1. 下载基础镜像（python:3.10-slim）
2. 安装Python依赖（requirements.txt）
3. 复制项目文件到容器
4. 设置环境变量和暴露端口

**构建时间**：首次构建可能需要5-10分钟（下载基础镜像和安装依赖），后续构建会更快。

- `-p 8000:8000`：端口映射（主机端口:容器端口）

## 8. 常见问题

### 8.1 HTTP 502 错误
**问题**：浏览器访问 `0.0.0.0:8000` 出现 502 错误  
**解决**：使用 `http://localhost:8000` 或 `http://127.0.0.1:8000` 访问

### 8.2 ONNX 推理警告
**问题**：运行 `infer.py` 时出现形状不匹配警告  
```
Expected shape from model of {1} does not match actual shape of {56962} for output label
```
**说明**：这是 ONNX 模型的输出定义问题，不影响功能。预测结果已正确保存。  
**解决**：可以忽略此警告，或使用 pkl 模型进行推理。

### 8.3 PS 续行符错误
**问题**：PowerShell 中使用 `\` 续行报错  
**解决**：使用单行命令，不要在 PowerShell 中使用 `\` 续行

### 8.4 PowerShell 执行策略错误
**问题**：激活虚拟环境时出现 `无法加载文件 ... Activate.ps1，因为在此系统上禁止运行脚本` 错误  
**错误信息**：
```
.venv\Scripts\activate : 无法加载文件 E:\培训\week19\.venv\Scripts\Activate.ps1，因为在此系统上禁止运行脚本。
```

**解决方法**（按优先级排序）：

**方法1：使用调用操作符（推荐，无需修改系统设置）**
```powershell
& .venv\Scripts\Activate.ps1
```

**方法2：临时绕过执行策略（仅当前会话）**
```powershell
powershell -ExecutionPolicy Bypass -File .venv\Scripts\Activate.ps1
```

**方法3：修改当前用户的执行策略（永久生效）**
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```
然后正常使用 `.venv\Scripts\activate`

**方法4：使用 CMD 方式激活（如果上述方法都不行）**
```cmd
.venv\Scripts\activate.bat
```

**方法5：直接使用 Python（无需激活虚拟环境）**
```powershell
# 直接使用虚拟环境中的 Python
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe src/preprocess.py
```

### 8.9 API 预测结果错误（score 为 0）
**问题**：使用 `sample_data` 中的 JSON 文件测试 API 时，返回的 score 为 0 或预测结果不正确

**原因**：
- `sample_data` 中的 JSON 文件包含的是**标准化后的特征值**（来自 `test.parquet`）
- 但 API 期望输入**原始值**（未标准化），然后自己进行标准化
- 如果输入已经是标准化后的值，API 会再次标准化，导致双重标准化，预测结果错误

**解决方法**：

**方法1：使用修复脚本（推荐）**
```powershell
# 运行修复脚本，将 sample_data 中的 JSON 文件更新为原始值
python src\fix_sample_data.py
```
这个脚本会：
1. 从原始 CSV 数据中找到与标准化特征最匹配的原始样本
2. 将 JSON 文件中的特征值替换为原始值
3. 之后 API 就能正确预测了

**方法2：手动从原始数据生成样本**
如果需要生成新的样本文件，确保保存的是原始值而不是标准化后的值。

**方法3：直接使用原始值测试 API**
从原始 CSV 数据中提取特征值（未标准化的），直接用于 API 测试。

**验证修复**：
修复后，重新测试 API，高风险样本应该返回较高的 score（接近 1），而不是 0。

### 8.10 模型文件写入错误
**问题**：训练模型时出现 `Model file ... is not available for writes` 错误  
**错误信息**：
```
[LightGBM] [Fatal] Model file E:\培训\week19\Project_A\models\lgbm_model.txt is not available for writes
```

**可能的原因**：
1. 模型文件正在被其他程序使用（如文件资源管理器、文本编辑器、API 服务等）
2. 文件权限不足
3. 路径中的中文字符编码问题

**解决方法**：

**方法1：关闭占用文件的程序（推荐）**
1. 关闭所有可能打开该文件的程序（文件资源管理器、文本编辑器、IDE等）
2. 如果 API 服务正在运行，先停止它（按 `Ctrl+C` 或关闭终端）
3. 重新运行训练脚本

**方法2：手动删除旧文件**
```powershell
# 进入项目目录
cd E:\培训\week19\Project_A

# 删除旧的模型文件
Remove-Item models\lgbm_model.txt -ErrorAction SilentlyContinue
Remove-Item models\lgbm_model.pkl -ErrorAction SilentlyContinue
Remove-Item models\lgbm_model.onnx -ErrorAction SilentlyContinue

# 重新训练
python src\train_lgbm.py
```

**方法3：检查文件权限**
```powershell
# 检查文件属性
Get-Item models\lgbm_model.txt | Select-Object FullName, Attributes, IsReadOnly

# 如果文件是只读的，取消只读属性
Set-ItemProperty -Path models\lgbm_model.txt -Name IsReadOnly -Value $false
```

**方法4：使用管理员权限运行**
如果权限问题持续存在，尝试以管理员身份运行 PowerShell，然后重新执行训练脚本。

**注意**：代码已更新，现在会自动尝试删除旧文件。如果问题仍然存在，请使用上述方法手动处理。
