# 数据说明与模型作用详解

## 一、JSON数据结构说明

### 1.1 整体结构

```json
{
  "features": {
    "Time": 0.0,
    "V1": -1.3598,
    "V2": -0.0727,
    ...
    "Amount": 149.62
  }
}
```

这是一个**API请求体**，用于向我们的预测服务发送数据。结构说明：
- **外层对象**：包含一个 `features` 键
- **`features` 对象**：包含30个特征值，代表一笔信用卡交易的各项指标

---

## 二、特征字段详细说明

### 2.1 特征分类

这30个特征可以分为三类：

#### 类别1：时间特征（1个）
- **`Time`**: 交易时间
  - **含义**：从第一笔交易开始经过的秒数
  - **示例值**：`0.0` 表示这是数据集中的第一笔交易
  - **作用**：帮助模型识别交易的时间模式（如深夜交易风险更高）

#### 类别2：PCA主成分特征（28个）
- **`V1` 到 `V28`**: 匿名化的主成分特征
  - **含义**：原始特征经过PCA（主成分分析）降维后的结果
  - **为什么匿名化**：为了保护用户隐私，原始特征（如商户类型、地理位置等）被转换为无法直接识别的数值
  - **数值范围**：通常是标准化后的数值，范围在 -3 到 +3 之间
  - **作用**：这些特征综合反映了交易的多个维度信息，如：
    - 交易金额模式
    - 商户类型特征
    - 地理位置特征
    - 交易频率特征
    - 用户行为模式等

#### 类别3：金额特征（1个）
- **`Amount`**: 交易金额
  - **含义**：本次交易的金额（单位：原始货币单位）
  - **示例值**：`149.62` 表示交易金额为149.62
  - **注意**：在输入模型前，这个值会被标准化（转换为均值为0、标准差为1的分布）
  - **作用**：异常金额可能是欺诈的指标

## 三、为什么数值看起来很奇怪？

### 3.1 标准化后的数值

你看到的数值（如 `-1.3598`、`0.4624`）是**标准化后的数值**，不是原始值。

**标准化公式**：
```
标准化值 = (原始值 - 平均值) / 标准差
```

**示例**：
- 如果 `V1` 的平均值是 `0.5`，标准差是 `1.2`
- 原始值 `-1.13` 标准化后 = `(-1.13 - 0.5) / 1.2 = -1.3598`

### 3.2 为什么需要标准化？

1. **消除量纲影响**：不同特征的数值范围差异很大
   - `Time` 可能是几万秒
   - `Amount` 可能是几百元
   - `V1-V28` 可能是小数

2. **加速模型训练**：标准化后的数据让模型更容易学习

3. **提高预测准确性**：避免某些特征因为数值大而主导模型

## 四、模型的作用和预测流程

### 4.1 模型的作用

我们的模型（LightGBM）是一个**二分类模型**，用于判断：
- **输入**：30个特征值
- **输出**：这笔交易是**正常交易**还是**欺诈交易**

### 4.2 预测流程详解

#### 步骤1：接收数据
```
API接收到JSON请求
↓
提取 features 对象中的30个特征值
```

#### 步骤2：数据验证
```
检查是否包含所有30个特征
检查特征顺序是否正确
检查数据类型是否正确
```

#### 步骤3：特征标准化（如果需要）
```
如果输入的是原始值，使用训练时保存的标准化器进行转换
如果输入已经是标准化值，跳过此步骤
```

#### 步骤4：模型预测
```
将30个特征值输入LightGBM模型
↓
模型内部处理：
  1. 遍历决策树
  2. 根据特征值在每个节点进行判断
  3. 最终到达叶子节点
  4. 计算所有树的加权平均
↓
输出：风险分数（0-1之间的浮点数）
```

#### 步骤5：生成预测结果
```
风险分数 >= 0.5 → 预测为欺诈（label = 1）
风险分数 < 0.5  → 预测为正常（label = 0）
```

#### 步骤6：生成解释（可选）
```
使用SHAP分析：
  - 计算每个特征对预测结果的贡献度
  - 找出影响最大的前10个特征
  - 说明哪些特征增加了风险，哪些降低了风险

使用LLM生成解释：
  - 将SHAP结果转换为通俗易懂的中文
  - 解释为什么模型给出这个预测
  - 如果是高风险，生成策略建议
```

## 五、模型如何"理解"这些特征？

### 5.1 决策树的工作原理

LightGBM使用**决策树**进行预测，就像问一系列问题：

```
问题1: V14 < -0.5?
  ├─ 是 → 问题2: V4 > 1.0?
  │         ├─ 是 → 高风险（欺诈概率0.8）
  │         └─ 否 → 中风险（欺诈概率0.3）
  └─ 否 → 问题3: Amount > 100?
            ├─ 是 → 低风险（欺诈概率0.1）
            └─ 否 → 正常（欺诈概率0.05）
```

### 5.2 特征重要性

模型会学习哪些特征最重要：

**高重要性特征示例**：
- `V14`: 通常是最重要的特征，可能反映交易的核心风险模式
- `V4`: 可能反映商户类型或交易模式
- `V12`: 可能反映地理位置或时间模式
- `Amount`: 交易金额，异常金额是重要指标

**特征重要性排序**（示例）：
1. V14 (重要性: 0.25)
2. V4 (重要性: 0.15)
3. V12 (重要性: 0.10)
4. Amount (重要性: 0.08)
5. V10 (重要性: 0.07)
...

### 5.3 特征组合

模型不仅看单个特征，还会学习特征之间的**组合关系**：

**示例组合**：
- `V14 < -0.5` **且** `V4 > 1.0` → 高风险
- `Amount > 500` **且** `Time` 在深夜 → 高风险
- `V12` 正常 **且** `V17` 正常 → 低风险

## 六、实际预测示例

### 6.1 示例数据解读

让我们分析你提供的示例数据：

```json
{
  "Time": 0.0,        // 第一笔交易
  "V1": -1.3598,      // 负值，可能表示某种低风险模式
  "V2": -0.0727,      // 接近0，中性
  "V3": 2.5363,       // 较大的正值，可能表示某种风险模式
  "V4": 1.3782,       // 正值，可能增加风险
  "V5": -0.3383,      // 负值，可能降低风险
  ...
  "Amount": 149.62    // 中等金额
}
```

### 6.2 预测过程（简化）

1. **模型分析**：
   - V3 = 2.5363（较大正值）→ 可能增加风险
   - V4 = 1.3782（正值）→ 可能增加风险
   - V14 = -0.3112（负值）→ 可能降低风险
   - 其他特征的综合影响

2. **综合判断**：
   - 模型会综合考虑所有30个特征
   - 计算加权风险分数
   - 假设最终分数 = 0.1234

3. **结果输出**：
   ```json
   {
     "score": 0.1234,  // 风险分数（0-1之间）
     "label": 0        // 0 = 正常，1 = 欺诈
   }
   ```
   - 因为 0.1234 < 0.5，所以预测为**正常交易**

### 6.3 SHAP解释（示例）

模型会告诉我们哪些特征影响最大：

```json
{
  "top_features": [
    {
      "feature": "V14",
      "shap_value": -0.15,  // 负值表示降低风险
      "说明": "V14的负值显著降低了欺诈风险"
    },
    {
      "feature": "V3",
      "shap_value": 0.08,   // 正值表示增加风险
      "说明": "V3的较大正值略微增加了风险"
    },
    {
      "feature": "V4",
      "shap_value": 0.05,
      "说明": "V4的正值略微增加了风险"
    }
  ]
}
```

### 6.4 LLM解释（示例）

使用qwen3:4b生成的中文解释：

```
根据模型分析，该交易被判定为正常交易（风险分数：0.1234）。

主要影响因素分析：
1. V14特征（-0.15）：该特征的负值显著降低了欺诈风险，这是最重要的影响因素。
2. V3特征（+0.08）：该特征的正值略微增加了风险，但影响较小。
3. V4特征（+0.05）：该特征的正值略微增加了风险。

综合来看，虽然V3和V4略微增加了风险，但V14的强烈负向影响使得整体风险较低，因此模型判定为正常交易。
```

## 七、模型的实际应用价值

### 7.1 实时风险检测

**场景**：用户刷卡消费时
1. 交易数据实时传入系统
2. 提取30个特征
3. 模型在毫秒级内给出预测
4. 如果风险分数 > 0.5，触发风控措施

### 7.2 风控决策支持

**决策流程**：
```
风险分数 < 0.3  → 自动通过
风险分数 0.3-0.7 → 人工审核
风险分数 > 0.7  → 自动拒绝或冻结
```

### 7.3 可解释性

**为什么重要**：
- 传统规则系统：只能给出"触发规则X"，无法解释原因
- 我们的系统：可以解释"为什么是欺诈"，帮助：
  - 风控人员理解决策依据
  - 用户了解被拒绝的原因
  - 优化风控策略

## 八、数据来源说明

### 8.1 数据集背景

这些数据来自Kaggle的**信用卡欺诈检测数据集**：
- **来源**：欧洲信用卡交易数据
- **时间跨度**：2天的交易记录
- **总交易数**：约28万笔
- **欺诈比例**：约0.17%（高度不平衡）

### 8.2 特征处理过程

**原始数据** → **PCA降维** → **标准化** → **模型输入**

1. **原始特征**（已匿名化）：
   - 可能包含：商户类型、地理位置、交易时间、金额等
   - 为了保护隐私，这些特征被PCA转换

2. **PCA降维**：
   - 将原始特征转换为28个主成分（V1-V28）
   - 保留最重要的信息，去除冗余

3. **标准化**：
   - 将所有特征转换为标准正态分布
   - 便于模型学习

## 九、常见问题

### Q1: 为什么V1-V28是负数？

**A**: 这是PCA和标准化的结果。负值不表示"不好"，只是表示该特征值低于平均值。模型会学习如何解释这些数值。

### Q2: 如果缺少某个特征会怎样？

**A**: API会返回错误，提示缺少哪些特征。所有30个特征都是必需的。

### Q3: 模型准确率如何？

**A**: 
- **AUC**: 约0.9363（在测试集上）
- **准确率**: 约99.8%（因为欺诈样本很少）
- **召回率**: 约85%（能识别85%的欺诈交易）

### Q4: 如何获取示例数据？

**A**: 使用Project_A提供的脚本：
```bash
cd EDU/Project_A
python src/sample_json.py
```

### Q5: 可以输入原始金额吗？

**A**: 可以，但需要确保：
1. 所有特征都是原始值（未标准化）
2. API会自动进行标准化处理

如果输入的是标准化值，需要确保与训练时使用的标准化器一致。
